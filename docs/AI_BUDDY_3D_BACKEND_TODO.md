## 0. Юу болсон бэ (товч)

Freelancer-ийн хийсэн үнэгэн (Спарк) 3D загварыг админаар байршуулсан ч апп
дээр гарахгүй, зөвхөн PNG thumbnail харагдаж байв. Хоёр тусдаа шалтгаантай:

1. **Mobile талын алдаа** — GLB нь texture-ээ `bufferView`-д хадгалдаг атал
   апп зөвхөн `data:` base64 URI-тай зургийг задалдаг байсан. → зассан (#249).
2. **Файл хэт том** — байршуулсан GLB **111 MB** байсан. Утас ачаалж чадалгүй
   чимээгүй уначихдаг. → R2 дээрх файлуудыг гараар оновчилсон (доор §1).

Оновчлолын дүн:

| Файл | Өмнө | Одоо | Юу хийсэн |
| --- | --- | --- | --- |
| Үнэг (Спарк) | 110.1 MiB | **3.05 MiB** | texture 4K PNG ×6 → 512px JPEG ×2, normal/roughness map хассан, 52 blendshape-аас 8, морфын нормал хассан |
| `police.glb` | 33.1 MiB | **1.49 MiB** | texture 512px, 393,278 → 47,192 гурвалжин |

⚠️ **R2 дээр гараар хийсэн өөрчлөлт:** `buddy/models/` доторх 6 үнэгэн загвар
+ `police.glb` бүгд оновчилсон хувилбараар **дарагдсан** (түлхүүр өөрчлөгдөөгүй
тул DB хөндөгдөөгүй, админ дээр юу ч солих шаардлагагүй байсан). Эх хувилбарууд
`buddy/models/originals/` дор бүтнээрээ хадгалагдсан.

## 1. Байршуулалтын хамгаалалт (тэргүүн ээлжинд)

Одоо `upload.controller.ts` нь 3D загварт **200 MB** хүртэл зөвшөөрдөг
(`d415e79` commit-оор 50 → 200 MB болгосон). Яг тэр учраас 111 MB файл ороод,
апп дээр чимээгүй уначихсан. Админ ямар ч анхааруулга хараагүй.

- [ ] **Хэмжээний хязгаар 10–15 MB болгож бууруулах** (`.glb`/`.gltf` дээр).
      Татгалзахдаа ойлгомжтой монгол мессеж: «3D загвар 10 MB-аас хэтэрсэн
      байна (одоогийн файл: 111 MB). Texture-ээ 512–1024px болгож дахин
      экспортлоно уу.»
- [ ] **GLB-ийн толгойг серверт задалж шалгах** (JSON chunk-ийг унших нь
      хэдхэн мөр код — гадаад сан шаардахгүй):
      - `extensionsRequired` дотор **Draco / meshopt / KTX2** байвал татгалзах
        — апп эдгээрийг задалж чадахгүй (RN дээр WASM decoder алга).
      - `images[].mimeType` нь **PNG эсвэл JPEG** биш бол татгалзах (WebP,
        KTX2 задрахгүй → загвар texture-гүй саарал гарна).
      - `animations` хоосон бол **анхааруулга** (алдаа биш): «Энэ загварт
        анимаци байхгүй тул buddy хөдөлгөөнгүй болно.»
      - Гурвалжны тоо, texture-ийн хэмжээг админд харуулах.
- [ ] **Хамгийн сайн шийдэл: серверт автоматаар оновчлох.** Node дээр
      `sharp` (аль хэдийн байгаа) + `@gltf-transform/core` + `functions`-оор
      texture-ийг 512px JPEG болгож, ашиглагдаагүй map-уудыг хасахад 111 MB
      файл 3 MB болно (энэ баримтад дурдсан бүх тоо яг тэр аргаар гарсан).
      Ингэвэл админ юу байршуулсан ч апп дээр ажиллана.

## 2. R2 дээрх загваруудын менежмент

- [ ] **Хуучин файлууд хуримтлагдаж байна.** Админ дээр дахин байршуулах бүрд
      **шинэ түлхүүр** (`buddy/models/<uuid>.glb`) үүсдэг ба хуучин объект
      хэзээ ч устдаггүй. 2026-08-18-нд ганцхан үнэгэн загвар **6 удаа**
      орсон = 5 орхигдсон объект (оновчлохоос өмнө ~530 MB). Buddy-гийн
      `avatarAssetUrl` солигдоход хуучин объектыг устгах эсвэл тогтмол
      цэвэрлэх script хэрэгтэй.
- [ ] **`Cache-Control` тавих.** `uploadToR2` (`image-storage.service.ts`) нь
      `PutObjectCommand`-д `CacheControl` өгдөггүй тул апп загвараа дахин
      татах эрсдэлтэй. Загвар нь дахин бичигддэггүй (шинэ түлхүүр үүсдэг) тул
      `public, max-age=31536000, immutable` тохирно. *(Одоо байгаа 7 объект
      дээр гараар тавьсан.)*
- [ ] **`buddy/models/originals/` фолдерийг яах вэ** гэдгийг шийдэх — freelancer
      дээр эх файл байгаа бол устгаж болно (~500 MB зай чөлөөлнө).

## 3. Turn-ий хариу удаан (хэрэглэгчийн гол гомдол)

Апп дээр «бодож байна…» гэж удаан хүлээж байна. Mobile талаас шахах зүйл
дуусcан (рендэрийн ачааллыг хөнгөлж, дуу бичлэгийг моно 16 кГц болгож
~8 дахин багасгасан — #250). Үлдсэн хугацаа нь **серверийн pipeline**:
STT → LLM → TTS **дараалан** ажилладаг.

- [ ] **Хамгийн хямд ялалт: текстээ TTS хүлээхгүйгээр эхэлж буцаах.**
      Одоо аудио бэлэн болтол хариу огт ирдэггүй. Хоёр шаттай хариу
      (эхлээд `reply_text`, дараа нь `audio_url`) болговол хэрэглэгч
      хүлээх мэдрэмж хагасаар багасна.
- [ ] **`buddy_voice_cache`-ийн ашиглалтыг шалгах** — мэндчилгээ гэх мэт
      давтагддаг өгүүлбэрүүд cache-д ороод байгаа эсэх.
- [ ] **`/ai/buddy/rt/*` stream** аль хэдийн байгаа ч `BUDDY_REALTIME_ENABLED`
      унтраалттай. ⚠️ **Expo Go дээр ашиггүй** — RN-ий `fetch` нь SSE-г
      урсгалаар уншиж чаддаггүй, сервер хаагдсаны дараа бүтнээр нь уншина.
      Native build (dev client / TestFlight) дээр л жинхэнэ үр дүн өгнө.

## 4. Lip-sync (жинхэнэ болгох)

Одоогийн ам хөдөлгөөн нь **дүр эсгэсэн** — хоёр синусын муруйгаар ам нээж
хаадаг (`BuddyAvatar.tsx` → `mouthCurve`), аудио тоглох үед л ажиллана.
Дуудагдаж буй авиатай таарахгүй. Загварт ARKit-ийн `jawOpen`, `mouthFunnel`,
`mouthPucker`, `mouthSmileL/R`, `eyeBlinkL/R` blendshape-ууд **байгаа** тул
өгөгдөл нь ирвэл апп тэр дороо ашиглаж чадна.

- [ ] Turn-ий хариунд **viseme/timestamp** массив нэмэх боломжийг судлах.
      Анхны төлөвлөгөө (`docs/AI_BUDDY_PLAN.md`) ElevenLabs-ийн
      `with-timestamps`-д тулгуурладаг байсан ч TTS нь **Gemini** рүү
      шилжсэн (`3d544ea`) тул тэр зам одоо байхгүй. Сонголт: (а) Gemini
      timestamp өгдөг эсэхийг шалгах, (б) зөвхөн TTS-ийг ElevenLabs дээр
      үлдээх, (в) серверт аудионы далайцыг тооцоолж хөнгөн curve буцаах.

## 5. Контентын шаардлага (freelancer-т дамжуулах)

Одоогийн загварт **анимаци clip огт байхгүй** (`animations: []`) тул buddy
хөдөлгөөнгүй. Апп талд `emotionMap` → clip нэрийн бүх логик бэлэн, clip
ирмэгц нэмэлт код бичихгүйгээр ажиллана.

- [ ] Дараах clip-үүдийг **нэг GLB дотор** экспортлуулах (backend-ийн хүлээж
      буй нэрс — `BUDDY_EMOTIONS` + `BUDDY_GESTURES`, `src/common/enums`):
      - Заавал: `idle` (loop)
      - Дохио: `wave` · `small_nod` · `thumbs_up` · `think_pose` · `smile`
      - Сэтгэл хөдлөл: `happy` · `curious` · `thinking` · `surprised` ·
        `calm` · `encouraging` · `confused`
      - Практикт `idle` + `wave` + `happy` + `small_nod` + `think_pose`
        таван clip хамгийн үр дүнтэй; үлдсэнийг админы `emotionMap`-аар
        байгаа clip рүү заалгаж болно (ж: `confused → think_pose`).
- [ ] Техникийн шаардлага: араг яс нь одоогийнхтой **ижил**, blendshape-ууд
      **хэвээр**, texture **1024px-ээс хэтрэхгүй**, Draco/KTX2 **хэрэглэхгүй**,
      нийт файл **5 MB-аас доош**.

## Хавсралт — mobile талын хязгаарлалт (яагаад ийм шаардлага тавьж байгаа вэ)

- RN дээр **DOM зураг задлагч байхгүй**. three-ийн GLTFLoader texture-ээ
  задалж чаддаггүй тул апп өөрөө JS дээр задалдаг: **PNG** (`upng-js`) ба
  **JPEG** (`jpeg-js`) хоёрыг л. WebP/KTX2 → texture-гүй саарал загвар.
- Мөн шалтгаанаар **Draco/meshopt** задрахгүй (WASM decoder байхгүй).
- RN-ийн `fetch` нь бинар биеийг base64 болгож хөрвүүлдэг тул том файл
  санах ойг хоёр дахин иддэг (апп одоо XHR `arraybuffer` ашигладаг).
- JS дээр texture задлах хугацаа пикселийн тоотой шууд хамааралтай:
  1024² → 512² нь **4 дахин** хурдан. Avatar дэлгэц дээр ~300px харагддаг
  тул 512 хангалттай.
